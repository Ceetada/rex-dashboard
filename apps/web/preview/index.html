Mobile · 390 px

The surface this product is actually used from

Roughly three quarters of Nigerian smartphone users are on Android, most on metered data. These layouts were designed at this width rather than shrunk down to it.

Dashboard Light

Scroll inside the frame.

Ordering is a hierarchy, not a list of widgets. The balance clears the fold at 360×640 — verified, not assumed. Verification is one next action with visible progress rather than a six-item checklist, because checklists get dismissed. The gold appears exactly once, on Top up.

Dashboard Dark

The same component tree, no dark: variants.

Not an inversion. Surfaces step rather than flip, because a true inversion collapses surface distinctions on an OLED phone in daylight. Brand colours move up the ramp (600 → 300), so the primary fill becomes light and its foreground flips to ink.

Health plans

Exclusions are on the card, not behind a link. Discovering one at a hospital counter is the worst failure this product could produce. Benefits are database rows and nothing branches on plan tier, so a fourth plan is an insert. Renewal inside 30 days escalates to the warning tone.

Retirement Dark

Two sections, kept visually distinct because they are legally distinct. Savings are ours; the RSA belongs to the user's PFA. Every pension figure carries a provenance banner and a sync timestamp — someone deciding on retirement needs to know how old the number is.

Buy airtime

The idempotency key is generated once at mount and reused across retries, so tapping Buy twice on a flaky connection cannot charge twice. Network is detected from the number but stays overridable — ported numbers exist. Network brand colours live here and nowhere else in the system.

Sign in

Wrong email and wrong password return an identical message after identical work — otherwise the form is a free list of your customers. First sign-in from an unrecognised device triggers a step-up challenge even with 2FA off, because most takeovers present entirely valid credentials from a new device.

What actually running it found

Six bugs no amount of typechecking would catch

Everything typechecked, all 97 tests passed, and both apps built — and the app still could not be opened. These surfaced only once it was booted against a real database and driven in a real browser.

A password in the query string

When a submit landed before React hydrated, the form fell back to a native GET and produced /login?email=…&password=Correct-Horse7-Battery — into browser history, server access logs and the Referer header. Found because the dev server's chunks were 404ing, which is exactly the real-world case: a chunk that fails to load. Both forms now declare method="post", so the fallback carries credentials in a body and lands on a 405 instead of leaking them.

The container would have failed on first deploy

A tsconfig path mapping pointing at package source outside the project dragged tsc's inferred rootDir up to the workspace root, so nest build emitted dist/apps/api/src/main.js while the Dockerfile ran node dist/main.js.

The API crashed on boot

main.ts installed Nest's ValidationPipe, which requires class-validator, in an application that validates with Zod. Redundant as well as fatal.

An expired session showed a 500, not a login form

Access tokens live fifteen minutes, so that is the ordinary case for anyone returning to an open tab — not an edge case. There was also no login page at all, and / redirected straight to a dashboard requiring a session.

Local sign-in was impossible by construction

The step-up challenge sends an OTP by SMS; SMS is suppressed to unverified numbers; so the code could never arrive and nobody could get past the login screen. Outside production the code is now logged. No bypass — the real challenge still runs.

The balance truncated to “₦124,500…”

At 360 px the number collided with the Top up button. Truncating the one figure people open the app to read is the worst thing that card can do, so the balance now takes the full card width with the button moved above it.

Where the colour came from

Sampled from the logo, not invented

Counting pixels in the supplied artwork returns the wordmark green #006634, the diamond gold #FCCF02, and the paper beneath them — together about 78% of the image. Two of those decided the system's structure.

The green is dark enough to be a primary action colour. At 7.12:1 on white it clears AA for body text and AAA for large, so it works as a button fill, a link and a focus ring with no invented darker variant.

The gold is too light to ever carry white text — 1.49:1, nowhere near the 4.5:1 floor. That single fact demotes it from second primary to accent, and a test asserts the white-on-gold failure explicitly so nobody re-derives it later.

Run it yourself

Verified end to end

Every step below was executed and confirmed before publishing this page.

pnpm install
pnpm docker:up          # Postgres + Redis

cp apps/api/.env.example apps/api/.env
cp apps/web/.env.example apps/web/.env.local
# fill the 4 secrets:  openssl rand -base64 32

pnpm db:migrate
pnpm db:seed            # reference data
pnpm db:seed:demo       # the user shown above
pnpm dev                # web :3000 · api :4000 · docs :4000/api/docs

Then open http://localhost:3000 and sign in:
