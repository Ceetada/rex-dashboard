Design system & UI preview

A colour system that could only have come from this logo.

Three colours account for roughly 78% of the supplied artwork. Every ramp, token and screen below descends from them — generated in OKLCH, contrast-gated in CI, and pinned so the brand green and gold reach the interface byte-for-byte.

This is a static render, not the running app. The live product needs PostgreSQL and the NestJS API behind it. Everything here is built from the real components — the same Tailwind classes, compiled from the same source — with seeded data standing in for live responses. Use the theme toggle; both themes are designed, not inverted.

Where the palette came from

Sampled, not chosen

Counting pixels in the logo returns the wordmark green, the diamond gold, and the paper beneath them. Two of those three decided the system's structure on their own.

The green is dark enough to be a primary action colour. At 7.12:1 on white it clears AA for body text and AAA for large — so it works as a button fill, a link and a focus ring with no invented darker variant. Many brand greens don't.

The gold is too light to ever carry white text — 1.49:1, nowhere near the 4.5:1 floor. That single fact demotes it from second primary to accent, and the system enforces it: text-on-accent is always ink, and a test asserts the white-on-gold failure explicitly so nobody re-derives it in six months.

Gold is also rationed. It's 3.5% of the logo, and it's roughly that in the UI — one accent element per screen. Below, it appears exactly twice.

Accessibility is a build gate

45 pairings, asserted on every commit

Not a spot check — every foreground/background combination the system actually ships, in both themes, with translucent dark-theme tints flattened over their real backdrop before measurement. A sample:

White on gold-400 — asserted to fail 1.49:1 By design

The last row is a test that asserts a failure. It exists so the reason text-on-accent is ink stays documented in code rather than in someone's memory.

The gate caught two real problems during construction. Muted text had been tuned against white, where it reads 4.63:1 and looks fine — but it never sits on white in the product, it sits on the canvas and on inset panels, where that same value dropped to 4.21:1. And the first semantic success green landed close enough to the brand green that a "succeeded" badge read as a branded badge. Both were fixed before a single component existed.

Running it for real

The live app needs PostgreSQL and Redis behind the NestJS API. From the repository root: 

pnpm install
pnpm docker:up        # Postgres + Redis
pnpm db:migrate && pnpm db:seed
pnpm dev              # web :3000 · api :4000
