# Design system

Every value in this document is derived from `brand/evas-logo.jpg` and generated by `packages/design-tokens`. Nothing here was picked by eye.

---

## 1. What the logo gave us

Sampling the supplied artwork (1495×441) returns three colours accounting for ~78% of all pixels:

| Colour | Hex | Share | Role in the mark |
|---|---|---|---|
| Deep green | `#006634` | 32.5% | The `evas` wordmark |
| Gold | `#FCCF02` | 3.5% | The rotated diamond over the `a` |
| Off-white | `#F7F7F7` | 42.2% | The ground it sits on |

Three observations drove the system:

1. **The green is dark enough to be a primary action colour.** At 7.12:1 against white it clears AA for normal text and AAA for large — so it can be a button fill, a link colour and a focus ring without compromise. Many brand greens are not, and require an invented darker variant.

2. **The gold is very light.** White text on it reaches only 1.49:1. It can therefore never carry white text, which makes it an *accent*, not a second primary. The system enforces this with a token (`text-on-accent` is always ink) and a test that asserts the failure explicitly so nobody re-derives it later.

3. **The ground is warm-neutral, not pure white.** Cards are pure white and the canvas is `#F7F8F7`, which gives surfaces a free step of elevation without a shadow.

## 2. How the ramps are built

Scales are generated in **OKLCH**, not HSL or hand-picked hex.

HSL's lightness is not perceptual — `hsl(60, 100%, 50%)` (yellow) and `hsl(240, 100%, 50%)` (blue) are nominally the same lightness and differ by a factor of ten in perceived brightness. Ramps built that way have muddy darks and washed-out lights, and drift in hue as they go.

OKLCH fixes both. Each ramp:

- Interpolates **lightness** on a curve from `L≈0.977` (stop 50) to `L≈0.235` (stop 950).
- Holds **hue** constant down the entire scale.
- Tapers **chroma** at the extremes so tints do not go neon and shades do not go muddy.
- **Pins the seed colour verbatim at its anchor stop**, so the brand colour appears in the UI byte-for-byte rather than as an interpolation that happens to land nearby.

Out-of-gamut colours are mapped by binary-searching chroma downward, never by clipping lightness — clipping shifts hue, which is exactly what the OKLCH approach exists to prevent.

```
green-600 = #006634  ← the logo green, exactly
gold-400  = #FCCF02  ← the logo gold, exactly
```

`packages/design-tokens/src/contrast.test.ts` asserts these two identities. If a future tweak breaks them, CI fails, because at that point the UI is no longer the brand.

**neutral-600 was tuned against the darkest background muted text is allowed to sit on**, not against white. The first candidate (`#717672`) gives 4.63:1 on white and looks fine in isolation — then lands at 4.21:1 on `bg-subtle` and fails on every table header and inset panel in the product. The shipped value clears 4.66:1 there.

This was caught by the contrast test, not by review.

### Semantic colours

|---|---|---|---|

**Success was reseeded away from the brand green.** The first generation produced a success colour close enough to `#006634` that a "succeeded" badge read as a *branded* badge. It is now cooler and brighter, and solid success fills use stop 700 rather than 600 so white text clears 4.5:1.

## 4. Semantic tokens

Components never reference `palette.green[600]`. They reference roles:

```
bg-canvas · bg-surface · bg-subtle · bg-hover
bg-primary · bg-primary-hover · bg-primary-subtle
bg-accent · bg-accent-subtle
bg-{success,warning,danger,info} · bg-{…}-subtle
text-primary · text-muted · text-subtle
text-on-primary · text-on-accent · text-brand
text-{success,warning,danger,info}
border-subtle · border-default · border-strong · border-primary
ring-focus
```

This indirection is what lets both themes swap underneath without touching a component. **The `dark:` variant should be essentially absent from the codebase** — if it starts appearing, a semantic token is missing.

### The dark theme is not an inversion

Two rules:

- **Surfaces step, they do not flip.** `#161A17` canvas → `#1D231F` surface → `#252C27` subtle. A true inversion collapses surface distinctions on OLED phones in daylight, which is where a lot of this product gets used.
- **Brand and semantic colours move *up* the ramp** (600 → 300). Saturated darks disappear against a dark canvas. Consequently `text-on-primary` flips from white to ink, because the dark-theme primary fill is light.

## 5. Accessibility is a build gate

`contrast.test.ts` asserts **45 pairings** across both themes on every CI run. Not a spot check — every foreground/background combination the system actually ships, with translucent dark-theme tints flattened over their real backdrop before measurement.

It caught two genuine failures during construction:

1. Muted text tuned against white, failing on the canvas and subtle surfaces (§3).
2. Semantic success colliding with brand green on solid fills (§3).

Both were fixed before any component existed. That is the point of gating rather than reviewing.

Additional rules the system enforces:

- **Status is never colour alone.** Every status badge pairs its tint with a word (`statusTone()` in `badge.tsx` is the single mapping).
- **Focus is always visible.** `focus-visible` with a 2px ring plus offset, ≥3:1 in both themes. Never removed, never a variant.
- **Placeholders use `text-muted`, not `text-subtle`.** A placeholder is still text someone has to read. `text-subtle` is for disabled states only.
- **Touch targets are ≥44px.** The default button height is 44px because this product is used on phones.
- **Zoom is never disabled.** `maximumScale: 5`.
- **Reduced motion is honoured globally**, emitted into `theme.css` by the generator.

## 6. Typography

**Geist**, with Inter as fallback — an engineered grotesque in the register this product is aiming at (Vercel, Linear, Stripe).

| Token | Size | Line height | Tracking | Use |
|---|---|---|---|---|
| `display-lg` | `clamp(2.25rem, 1.6rem + 2.4vw, 3.25rem)` | 1.06 | −0.03em | Marketing headline |
| `display-sm` | `clamp(1.75rem, 1.4rem + 1.4vw, 2.25rem)` | 1.12 | −0.025em | Page title |
| `heading-lg` | 1.5rem | 1.25 | −0.02em | Section |
| `heading-md` | 1.25rem | 1.3 | −0.015em | Subsection |
| `heading-sm` | 1.0625rem | 1.35 | −0.01em | Card title |
| `body-lg` | 1rem | 1.6 | 0 | Long form |
| `body-md` | 0.9375rem | 1.55 | 0 | Default |
| `body-sm` | 0.875rem | 1.5 | 0 | Dense UI |
| `caption` | 0.8125rem | 1.45 | 0.005em | Metadata |
| `overline` | 0.6875rem | 1.4 | **0.08em** | All-caps labels |
| `numeric` | 1.75rem | 1.15 | −0.02em | **Balances** |

Two deliberate choices:

- **Display sizes are fluid; body sizes are not.** Headlines should adapt to viewport. Body text should not — a user who has set their browser text size means it.
- **`overline` carries +0.08em tracking.** All-caps at 11px without positive tracking sets as an unreadable block.

**Tabular figures are mandatory on every numeric surface.** `font-variant-numeric: tabular-nums` is applied via `.tabular` and `[data-numeric]`. Without it, a balance updating from ₦1,111 to ₦8,888 visibly jitters as glyph widths change — which reads as instability on a screen showing someone their money.

## 7. Space, radius, elevation, motion

**Space** — 4px base grid. Everything lands on a multiple.

**Radius** — the logo's diamond is a hard-edged rotated square, so the system avoids pill-shaped everything. Controls: 6–8px. Cards: 12–16px. Balance card: 20px. `full` is reserved for badges and avatars.

**Elevation** — shadows are tinted with the brand hue (`rgba(11, 26, 18, …)`) rather than pure black. Neutral-black shadows over a warm-grey canvas read as dirty. Kept shallow; elevation comes mainly from borders and surface steps.

**Motion** — durations are short (80–340ms) because this is a utility product people open to do one task.

| Easing | Curve | Use |
|---|---|---|
| `standard` | `cubic-bezier(0.2, 0, 0, 1)` | Most transitions |
| `entrance` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | Elements arriving — decelerate |
| `exit` | `cubic-bezier(0.3, 0, 0.8, 0.15)` | Elements leaving — accelerate |
| `spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Small delightful overshoots only |

Every one of these is disabled under `prefers-reduced-motion`.

## 8. Where third-party colour is allowed

Exactly one place: **network selection**.

MTN yellow, Airtel red, Glo green and 9mobile green are how Nigerians identify their line at a glance. Recolouring them into our palette would make the control measurably slower to use. They are confined to `network-picker.tsx`, never enter the token system, and selection is still communicated by a checkmark and ring rather than by colour alone.

## 9. Regenerating

```bash
pnpm tokens   # regenerates packages/design-tokens/dist/theme.css
pnpm --filter @evas/design-tokens test   # 45 contrast assertions
```

`theme.css` is committed so the web app builds without running the generator. Edit the TypeScript sources, never the generated CSS.
